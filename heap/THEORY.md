# Теоретичні відомості про піраміди (Heap)

## Що таке піраміда (Heap)?

**Піраміда** - це повне двійкове дерево, яке задовольняє властивість піраміди:
- **Max-Heap**: значення кожного вузла >= значень його нащадків
- **Min-Heap**: значення кожного вузла <= значень його нащадків

## Представлення піраміди масивом

Піраміда зберігається у вигляді масиву, де для елемента з індексом `i`:

```
Parent(i) = (i - 1) / 2     // Батьківський вузол
Left(i)   = 2 * i + 1       // Лівий нащадок
Right(i)  = 2 * i + 2       // Правий нащадок
```

### Приклад Max-Heap:

```
Візуальне представлення:
        16
       /  \
      14   10
     / \   / \
    8   7 9   3
   / \
  2   4

Представлення масивом:
[16, 14, 10, 8, 7, 9, 3, 2, 4]
 0   1   2   3  4  5  6  7  8
```

## Основні операції

### 1. MaxHeapify (підтримка властивості Max-Heap)

**Призначення**: відновлює властивість max-heap для піддерева з коренем у вузлі `i`

**Алгоритм**:
```
MaxHeapify(A, heapSize, i):
    l = Left(i)
    r = Right(i)
    largest = i
    
    if l < heapSize AND A[l] > A[largest]:
        largest = l
    
    if r < heapSize AND A[r] > A[largest]:
        largest = r
    
    if largest ≠ i:
        swap A[i] with A[largest]
        MaxHeapify(A, heapSize, largest)
```

**Складність**: O(log n)

### 2. BuildMaxHeap (побудова піраміди)

**Призначення**: перетворює невпорядкований масив на max-heap

**Алгоритм**:
```
BuildMaxHeap(A, n):
    for i = n/2 - 1 downto 0:
        MaxHeapify(A, n, i)
```

**Пояснення**: 
- Елементи від n/2 до n-1 є листями дерева
- Починаємо з останнього внутрішнього вузла (n/2 - 1)
- Рухаємось до кореня, виконуючи MaxHeapify

**Складність**: O(n)

### 3. HeapSort (пірамідальне сортування)

**Алгоритм для сортування за зростанням**:
```
HeapSort(A, n):
    BuildMaxHeap(A, n)              // Крок 1: побудувати max-heap
    
    for i = n-1 downto 1:           // Крок 2: витягувати max елементи
        swap A[0] with A[i]         // Найбільший на кінець
        MaxHeapify(A, i, 0)         // Відновити heap для A[0..i-1]
```

**Чому це працює?**:
1. Після BuildMaxHeap найбільший елемент знаходиться в A[0]
2. Міняємо його місцями з останнім елементом
3. Зменшуємо розмір піраміди на 1
4. Відновлюємо властивість max-heap для зменшеної піраміди
5. Повторюємо поки не відсортуємо весь масив

**Складність**: O(n log n)

## Операції черги з пріоритетами

### Max-Heap як черга з пріоритетами

1. **HeapMax** - повернути максимум
```
HeapMax(A, heapSize):
    if heapSize < 1:
        error "heap underflow"
    return A[0]
```
Складність: O(1)

2. **HeapExtractMax** - видалити і повернути максимум
```
HeapExtractMax(A, heapSize):
    if heapSize < 1:
        error "heap underflow"
    max = A[0]
    A[0] = A[heapSize - 1]
    heapSize = heapSize - 1
    MaxHeapify(A, heapSize, 0)
    return max
```
Складність: O(log n)

3. **HeapIncreaseKey** - збільшити значення елемента
```
HeapIncreaseKey(A, i, key):
    if key < A[i]:
        error "new key is smaller than current key"
    A[i] = key
    while i > 0 AND A[Parent(i)] < A[i]:
        swap A[i] with A[Parent(i)]
        i = Parent(i)
```
Складність: O(log n)

4. **MaxHeapInsert** - додати новий елемент
```
MaxHeapInsert(A, heapSize, key, maxSize):
    if heapSize >= maxSize:
        error "heap overflow"
    heapSize = heapSize + 1
    A[heapSize - 1] = -∞
    HeapIncreaseKey(A, heapSize - 1, key)
```
Складність: O(log n)

## Min-Heap

Всі операції для Min-Heap аналогічні, але з протилежними порівняннями:
- `>` замінюється на `<`
- max замінюється на min
- increase замінюється на decrease

## Застосування піраміди

1. **Пірамідальне сортування** (HeapSort)
   - Сортування "на місці" без додаткової пам'яті
   - Гарантована складність O(n log n)

2. **Черга з пріоритетами**
   - Планувальники операційних систем
   - Системи обробки подій
   - Алгоритм Дейкстри (найкоротший шлях)
   - Алгоритм Прима (мінімальне остовне дерево)

3. **K найбільших/найменших елементів**
   - Top-K проблема
   - Медіана потоку даних

4. **Злиття відсортованих послідовностей**
   - Зовнішнє сортування
   - Злиття великих файлів

## Переваги та недоліки

### Переваги:
- ✅ Ефективна побудова: O(n)
- ✅ Сортування "на місці": O(1) додаткової пам'яті
- ✅ Швидкий доступ до max/min: O(1)
- ✅ Ефективні операції вставки/видалення: O(log n)
- ✅ Гарантована складність O(n log n) для сортування

### Недоліки:
- ❌ Не стабільне сортування
- ❌ Гірша локальність доступу до пам'яті ніж у Quicksort
- ❌ Не підходить для пошуку довільного елемента

## Порівняння з іншими структурами

| Операція | Heap | Відсортований масив | Невідсортований масив |
|----------|------|---------------------|----------------------|
| Вставка | O(log n) | O(n) | O(1) |
| Видалення max/min | O(log n) | O(1) | O(n) |
| Пошук max/min | O(1) | O(1) | O(n) |
| Побудова | O(n) | O(n log n) | O(1) |

## Приклади роботи алгоритмів

### Приклад BuildMaxHeap

Вхідний масив: [4, 10, 3, 5, 1]

```
Крок 0: Початковий стан
    4
   / \
  10  3
 / \
5   1

Крок 1: MaxHeapify(A, 5, 1) - індекс 1 (значення 10)
Left=3 (значення 5), Right=4 (значення 1)
10 > 5 і 10 > 1, нічого не міняємо

Крок 2: MaxHeapify(A, 5, 0) - індекс 0 (значення 4)
Left=1 (значення 10), Right=2 (значення 3)
10 > 4, міняємо місцями A[0] та A[1]

    10
   /  \
  4    3
 / \
5   1

Потім викликаємо MaxHeapify(A, 5, 1)
Left=3 (значення 5), Right=4 (значення 1)
5 > 4, міняємо місцями A[1] та A[3]

    10
   /  \
  5    3
 / \
4   1

Результат: [10, 5, 3, 4, 1]
```

### Приклад HeapSort

Масив після BuildMaxHeap: [10, 5, 3, 4, 1]

```
Ітерація 1:
- Міняємо A[0] з A[4]: [1, 5, 3, 4, 10]
- MaxHeapify для A[0..3]: [5, 4, 3, 1, 10]

Ітерація 2:
- Міняємо A[0] з A[3]: [1, 4, 3, 5, 10]
- MaxHeapify для A[0..2]: [4, 1, 3, 5, 10]

Ітерація 3:
- Міняємо A[0] з A[2]: [3, 1, 4, 5, 10]
- MaxHeapify для A[0..1]: [3, 1, 4, 5, 10]

Ітерація 4:
- Міняємо A[0] з A[1]: [1, 3, 4, 5, 10]

Результат: [1, 3, 4, 5, 10] - відсортовано за зростанням!
```

## Інваріанти піраміди

**Властивість Max-Heap**: для всіх i (крім кореня):
```
A[Parent(i)] >= A[i]
```

**Властивість Min-Heap**: для всіх i (крім кореня):
```
A[Parent(i)] <= A[i]
```

Ці властивості завжди повинні виконуватись після кожної операції!

## Висновок

Піраміда - це потужна структура даних, яка:
- Ефективно підтримує операції з пріоритетами
- Забезпечує гарантоване O(n log n) сортування
- Використовує мінімальну додаткову пам'ять
- Має широке практичне застосування

Розуміння піраміди є фундаментальним для вивчення алгоритмів та структур даних!
